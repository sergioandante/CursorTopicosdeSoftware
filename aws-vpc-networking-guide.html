How your AWS network is isolated, addressed and routed

Four slides, taken apart piece by piece: account resource isolation, the main route table, public subnets and private subnets. Every flow is animated step by step, and you can break things on purpose to see where packets die.

The big picture in 30 seconds

An AWS account holds your resources. Inside a Region you get a VPC — your own private network — that spans the Region's Availability Zones. You carve the VPC's address range into subnets (each in one AZ). A route table decides where each packet goes. If a subnet's route table has a route to an internet gateway, the subnet is public; if not, it is private.

2 Addresses first: private IPs and CIDR blocks

The slides write 10.0.0.0/16 for the VPC and 10.0.0.0/20, 10.0.128.0/20 for subnets. The number after the slash says how many of the 32 address bits are fixed (the network part). The rest are free for hosts.

🧩 Carving 10.0.0.0/16 into /20 subnets

Going from /16 to /20 fixes 4 more bits → 2⁴ = 16 subnets of 4,096 addresses each. The slides' subnets are block 0 (Subnet_A) and block 8 (Subnet_B). Click a block, or test an IP:

➕ Beyond the slides

AWS reserves 5 addresses in every subnet (the first four and the last), so a /20 offers 4,091 usable addresses. 198.51.102.7 is a public address; 10.x.x.x addresses are private — not routable on the internet.

3 Slide 2 · The main route table

Animated flowSimulation

Slide: Amazon VPC 10.0.0.0/16 with Subnet_A 10.0.0.0/20 (EC2 instance A, 10.0.0.5) and Subnet_B 10.0.128.0/20 (EC2 instance B, 10.0.134.60), both using the main VPC route table that has a single route: 10.0.0.0/16 → local.

What the route says

«Any packet whose destination is inside 10.0.0.0/16 is delivered locally, inside the VPC.» That is why A and B can reach each other without any gateway, even though they are in different subnets.

🔎 How the table is read: longest prefix match

A route table can have several routes that match one destination. The most specific one wins (longest prefix). Try destinations. (The third route is an extra example, ➕ beyond the slides.)

4 Slide 3 · Public subnets

Animated flowBreak it on purpose

Slide: a public subnet with an associated internet gateway allows direct access to the internet, and every instance in a public subnet requires a private and a public IP address to gain internet access. Its route table has two routes: 10.0.0.0/16 → local and 0.0.0.0/0 → Internet gateway ID.

Reading 0.0.0.0/0

A /0 prefix fixes zero bits: it matches every address. It is the default route — the catch-all for anything that isn't more specific (like the VPC's own /16). Packets to the internet fall through to it.

Experiment: run the outbound packet, then break it: remove the public IP, detach the gateway, or delete the default route. Each failure dies at a different place.

What the internet gateway does (➕ beyond the slides)

Your instance only knows its private address 10.0.0.5. The IGW performs a one-to-one address translation: outbound it rewrites the source to the public IP 198.51.102.7; for the reply it rewrites the destination back to 10.0.0.5. Without a public IP there is nothing to translate to. Security groups and network ACLs also filter traffic; this guide doesn't model them.

5 Slide 4 · Private subnets

Animated flowSimulation

Slide: a private subnet does not have direct access to the internet. Its route table contains only 10.0.0.0/16 → local; the instance has only a private IP. Same instance, same VPC — only the route table differs.

Key insight

«Public» and «private» aren't properties you set on a subnet — they come from its route table. Tick «Add 0.0.0.0/0 → IGW to this table» above: the subnet turns public instantly. But the instance still can't reach the internet until it also has a public IP: two independent conditions.

➕ Beyond the slides

Private-subnet instances that must reach the internet (e.g. for updates) usually go through a NAT gateway placed in a public subnet: the private route table gets 0.0.0.0/0 → NAT gateway, so outbound works but nothing can start a connection into the instance.
